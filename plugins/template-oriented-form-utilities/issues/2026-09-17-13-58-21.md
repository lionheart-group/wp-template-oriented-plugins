# Chore: Drop the Transitional Hidden-Field and Nonce-Action Fallbacks

**Date:** 2026-09-17
**Status:** Open

---

## Overview

Two changes shipped together left behind transitional fallbacks that exist only to carry visitors
across a single plugin update, and should be removed once they can no longer matter:

1. The plugin's hidden form fields moved to a `__tofu_` prefix. The old names are still read.
2. The redirect flow's nonce action gained the form key. The old bare action is still accepted.

Both exist for the same reason: a visitor who loaded a form page before the update and submitted it
afterwards carries the old spelling in their POST body.

---

## Background

### The nonce action

The redirect flow used to mint its nonce against a bare `'input'` / `'confirm'` action, which meant
a nonce issued for one form verified against any other form — the REST flow had bound the form key
into the action for exactly this reason (`Consts::REST_NONCE_ACTION_FORMAT`, and the comment at
`src/Init/RestEndpoint.php:229`), but the redirect flow was never updated to match. Binding the key
in (`Consts::NONCE_ACTION_FORMAT`) closed that gap, but invalidated every nonce already sitting in a
browser — a 403 on submit without the fallback.

### The field names

`_tofu_{key}_nonce`, `_tofu_recaptcha_token` and `_tofu_turnstile_token` became `__tofu_…` so that
every field the plugin owns shares one prefix, which `FormConfig` also reserves. An in-flight page
posts the old names; without the fallback the nonce one is a 403 and the token ones are a
"token is missing" validation error.

| Component | Location |
|---|---|
| Legacy name constants | `src/Consts.php` — `LEGACY_NONCE_FORMAT`, `LEGACY_RECAPTCHA_TOKEN_INPUT_NAME`, `LEGACY_TURNSTILE_TOKEN_INPUT_NAME` |
| Nonce field-name fallback | `src/Models/Form.php` — `verifyNonceField()`, the `?? $post[$legacyNonceKey]` read |
| Nonce action fallback | `src/Models/Form.php` — `verifyNonceField()`, the `$legacyAction` branch |
| Callers passing a legacy action | `src/Models/Form.php` — `actionInput()` (`'input'`), `actionConfirm()` (`'confirm'`) |
| Token field-name fallbacks | `src/Models/Form.php` — `verifyRecaptcha()`, `verifyTurnstile()` |
| REST equivalent (no fallback needed — always bound) | `src/Consts.php` — `REST_NONCE_ACTION_FORMAT` |

---

## Goals

1. Remove both fallbacks once no browser can still be holding a pre-update page.
2. Leave the `__tofu_` field names and the form-key-bound nonce action as the only accepted forms.

---

## Detailed Tasks

### 1. Wait for the nonce lifetime to pass

WordPress nonces are valid for at most 24 hours (two 12-hour ticks), which also bounds how long a
form page is usefully submittable. Once the release carrying the change has been out longer than
that, no legitimate visitor can still hold an old-spelling page. Removing the fallbacks in the
*next* release after that one is the simple, safe rule.

### 2. Remove the fallbacks

- `src/Consts.php` — delete the three `LEGACY_*` constants and their shared docblock.
- `src/Models/Form.php`, `verifyNonceField()` — drop `$legacyNonceKey` and the `??` that reads it;
  drop the `?string $legacyAction = null` parameter, its docblock entry, the transitional comment,
  and the second `wp_verify_nonce()` branch.
- `src/Models/Form.php` — drop the third argument from the `verifyNonceField()` calls in
  `actionInput()` and `actionConfirm()`.
- `src/Models/Form.php`, `verifyRecaptcha()` / `verifyTurnstile()` — drop the
  `?? $post[Consts::LEGACY_…]` reads and the comments above them.
- `src/Init/RestEndpoint.php` passes no legacy action, so its two call sites need no change.

### 3. Tests

`tests/Unit/Models/FormNonceActionTest.php` covers the fallback explicitly, under a
"Transitional fallback" heading. Delete those cases and keep the ones pinning that a nonce minted
for one form, or for another step, is rejected.

### 4. readme.txt

The "Unreleased" upgrade notice tells integrators the old field names are accepted "for one
release". Once that stops being true, make sure the released notice reflects it.
